# Gelato Central — Απόδοση

**Δεν έγινε καμία μέτρηση χρόνου.** Ό,τι ακολουθεί προέρχεται από ανάγνωση κώδικα: σχήμα ερωτημάτων, πλήθος ερωτημάτων ανά σελίδα, απουσία ορίων. Κανένα ποσοστό ή χρόνος δεν αναφέρεται, γιατί δεν υπάρχει. Το πρώτο βήμα του σχεδίου για την απόδοση είναι ακριβώς η μέτρηση (βήμα P0 στο `REMEDIATION_PLAN.md`).

Τα ευρήματα αναφέρονται με τον κωδικό τους από το `AUDIT_REPORT.md`.

## Τι είναι ήδη σωστό

- Οι σελίδες είναι server components· δεν υπάρχει άντληση δεδομένων από τον browser, εκτός από το L27.
- Δεν βρέθηκε μοτίβο N+1 (`.map(async …)` ή `await db.` μέσα σε βρόχο) στις διαδρομές ανάγνωσης. Χρησιμοποιούνται `Promise.all` και `id: { in: … }`.
- 11 από τις κύριες λίστες σελιδοποιούνται στη βάση (αποδείξεις, συναλλασσόμενοι, είδη, προϊόντα, αγορές, παραγωγή, συνταγές, απόθεμα, υποστήριξη, χρήστες, ιχνηλασιμότητα).
- Η μόνη `"use cache"` συνάρτηση (`getProductPageData`) έχει το `orgId` στο κλειδί και ακυρώνεται σε κάθε εγγραφή.
- Ο service worker κρατά μόνο στατικά αρχεία· ποτέ σελίδες ή απαντήσεις API.
- Δεν βρέθηκε διαρροή μνήμης: καμία μεταβλητή σε επίπεδο module που μεγαλώνει, και οι listeners καθαρίζονται.
- Οι βιβλιοθήκες `pdfkit` και `exceljs` μένουν στον server.

## Τι μένει στο spec των λιστών

Οι εννέα λίστες με σταθερό όριο και χωρίς επόμενη σελίδα (M20), οι δύο χωρίς κανένα όριο (L33) και οι 27 χειροποίητοι πίνακες (L29) είναι ακριβώς το αντικείμενο του spec της κοινής σελιδοποιημένης λίστας. Εδώ δεν προτείνεται τίποτα γι' αυτές, για να μην γίνει η ίδια δουλειά δύο φορές.

## Πώς θα μετρηθεί (βήμα P0)

1. Προσωρινή τοπική βάση με τα migrations και ένα script που γεμίζει ρεαλιστικό όγκο για μία επιχείρηση: ενδεικτικά 2 χρόνια, 3 καταστήματα, 200.000 πωλήσεις, 5.000 τιμολόγια χονδρικής, 3.000 τιμολόγια αγοράς, 1.500 είδη. Οι αριθμοί θα οριστούν με τον Γιάννη ώστε να μοιάζουν με πραγματικό πελάτη.
2. Για κάθε σελίδα του πίνακα: πλήθος ερωτημάτων (log του Prisma), συνολικός χρόνος βάσης, χρόνος απόκρισης server, μέγιστη μνήμη, και `EXPLAIN (ANALYZE, BUFFERS)` για τα τρία βαρύτερα ερωτήματα.
3. Οι ίδιες μετρήσεις μετά από κάθε βήμα P1 έως P5. Στο `FINAL_REPORT.md` μπαίνουν μόνο αυτοί οι αριθμοί, πριν και μετά.

Αν η μέτρηση δείξει ότι κάποιο σημείο δεν είναι πρόβλημα στον ρεαλιστικό όγκο, το αντίστοιχο βήμα παραλείπεται.
