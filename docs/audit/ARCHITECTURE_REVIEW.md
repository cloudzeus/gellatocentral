# Gelato Central — Αρχιτεκτονική

Τα ευρήματα αναφέρονται με τον κωδικό τους από το `AUDIT_REPORT.md`.

## Τι είναι

SaaS πολλών επιχειρήσεων για καταστήματα παγωτού: συνδρομές, ταμείο (browser και Android), απόθεμα, αγορές, παραγωγή, χονδρική, οικονομικά, μισθοδοσία, HACCP, CRM, GDPR, υποστήριξη με AI.

| Κομμάτι | Τεχνολογία | Θέση |
|-|-|-|
| Εφαρμογή web | Next.js 16.4.5 (App Router, `cacheComponents`, `output: "standalone"`), React 19.3, Tailwind 4, shadcn | `web/` |
| Βάση | PostgreSQL 16 + pgvector + pg_trgm, Prisma 7.10 με `@prisma/adapter-pg` | `web/prisma/` |
| Ταμείο Android | Expo / React Native, πληρωμή μέσω Viva Terminal με deeplink | `mobile/` |
| Deploy | Dockerfile πολλών σταδίων στο Coolify, `prisma migrate deploy` σε κάθε εκκίνηση | `web/Dockerfile`, `web/docker-entrypoint.sh` |

## Στρώματα

```
Browser ──► proxy.ts (υπάρχει cookie;) ──► app/(app)/** σελίδες RSC ──► lib/*  ──► lib/db.ts ──► PostgreSQL
                                          └► server actions (actions.ts) ─┘
Android ──► app/api/pos/**  (Bearer token συσκευής)  ──► lib/pos.ts, lib/viva/*
Αισθητήρες ► app/api/devices/readings
Coolify cron ► app/api/cron/{subscriptions,haccp}  (Bearer CRON_SECRET)
Δημόσιοι σύνδεσμοι ► app/{b2b,rfq,vitrine,schedule}/[token]
```

- **`app/(app)/`**: 187 αρχεία. Οι σελίδες είναι server components που διαβάζουν απευθείας από το `lib/`. Οι εγγραφές γίνονται με server actions δίπλα στη σελίδα.
- **`app/api/`**: 27 route handlers, για ό,τι δεν είναι browser (συσκευές, cron) και για λήψεις αρχείων και εξαγωγές.
- **`lib/`**: 226 αρχεία, ένα module ανά τομέα. Τα `*-db.ts` κρατούν τις συναλλαγές, τα αντίστοιχα χωρίς `-db` την καθαρή λογική που ελέγχεται με unit tests.
- **`lib/db.ts`**: το μοναδικό σημείο δημιουργίας του Prisma client.

## Αποφάσεις που δουλεύουν και πρέπει να μείνουν

1. **Απομόνωση επιχείρησης στον κώδικα**: `currentOrg(permission)`, `requireStockContext`, `partyScope()`. Το πεδίο εφαρμογής βγαίνει πάντα από τον χρήστη, ποτέ από το URL.
2. **Απόθεμα ως ημερολόγιο**: μόνο `StockMovement`, χωρίς αποθηκευμένο υπόλοιπο. Όλες οι εγγραφές περνούν από το `postStockMovement` μέσα σε `stockTransaction` (Serializable, advisory locks, έως 3 προσπάθειες).
3. **Πύλη εγγραφών ανά επιχείρηση**: το `tenantWriteTransaction` κλειδώνει τη γραμμή της επιχείρησης, ώστε μετάβαση δεδομένων και κλείσιμο να μην συγκρούονται με εγγραφές.
4. **Εξωτερικές κλήσεις έξω από συναλλαγές**: δέσμευση, κλήση, ολοκλήρωση (myDATA, αποστολή παραστατικών, μισθοδοσία).
5. **`clientKey` + `requestHash`** για ασφαλή επανάληψη στις περισσότερες ροές χρήματος και αποθέματος.
6. **Ρυθμίσεις τρίτων από οθόνη** (πίνακας `Setting`) αντί για env. Σωστό για λειτουργία, με το κενό του H8.

## Αδυναμίες

| Θέμα | Ευρήματα | Σχόλιο |
|-|-|-|
| Το συμβόλαιο με το Android δεν προστατεύεται από τίποτα | C1, H2, H3, H4 | Δεν υπάρχει test ούτε κοινός τύπος ανάμεσα σε `mobile/api.ts` και `app/api/pos/*`. Η αλλαγή του server πέρασε χωρίς να το δει κανείς. Χρειάζεται contract test στα routes. |
| Ο `proxy.ts` είναι λίστα εξαιρέσεων | H1 | Κάθε νέα δημόσια διαδρομή πρέπει να θυμηθεί κάποιος να την προσθέσει. Χρειάζεται test που απαριθμεί τις δημόσιες διαδρομές. |
| Εργασίες παρασκηνίου μόνο ως δύο cron routes | M9, L3, L16 | Δεν υπάρχει ουρά ούτε καθαρισμός εκκρεμοτήτων (πωλήσεις σε αναμονή, κλειδωμένες διαβιβάσεις, ληγμένες συνεδρίες). Αρκεί ένα τρίτο task «καθαρισμός» στο υπάρχον cron· δεν χρειάζεται νέα υποδομή. |
| Πληρωμή συνδρομής δεμένη με απόδοση σελίδας | H5, H6 | Αλλαγή χρήματος μέσα σε GET σελίδας. Το webhook λύνει και τα δύο. |
| Ταμείο και απόθεμα δεν συνδέονται | H10 | Το μεγαλύτερο λειτουργικό κενό. Θέλει απόφαση προϊόντος πριν από κώδικα. |
| Ακεραιότητα μόνο στον κώδικα | M14, M17, M18, L19 | Η βάση δεν επιβάλλει όσα ο κώδικας τηρεί. Χαμηλή προτεραιότητα όσο ο κώδικας είναι σωστός, αλλά είναι το δίχτυ ασφαλείας που λείπει. |
| Παρατηρησιμότητα | L25 | Δεν υπάρχει δομημένο log, αναφορά σφαλμάτων, ούτε `instrumentation.ts`. Χωρίς αυτά δεν μπορεί να μετρηθεί τίποτα στην παραγωγή. |
| Όριο ρυθμού πουθενά | M3 | Μία μικρή κοινή συνάρτηση, στη μνήμη για έναν κόμβο (με σημείωση `shortcut:` για πολλούς). |

## Τι δεν προτείνεται

- **Καμία αναδόμηση φακέλων ή διάσπαση των μεγάλων αρχείων** (L31). Δεν έχει μετρήσιμο όφελος και θα συγκρουόταν με το PR #2 και το spec των λιστών.
- **Καμία νέα εξάρτηση**. Όλα τα παραπάνω γίνονται με ό,τι υπάρχει (`node:crypto`, `AbortSignal`, Prisma, zod).
- **Καμία αναβάθμιση framework**.
- **Καμία ουρά μηνυμάτων ή Redis**. Η εφαρμογή τρέχει σε έναν κόμβο· όταν γίνουν περισσότεροι, ο limiter και το κλείδωμα cron πάνε στη βάση.

## Επικαλύψεις με δουλειά σε εξέλιξη

- **PR #2** («Κανόνες UX… και οριζόντιο λογότυπο», ανοιχτό, 66 αρχεία, 1 έως 4 γραμμές στο καθένα). Οι αλλαγές του είναι διατύπωση κειμένων, άρα οι συγκρούσεις θα είναι λίγες και μηχανικές. **Πρόταση: να μπει πρώτα το PR #2 και η υλοποίηση να ξεκινήσει από το νέο `master`.**
- **Spec των 16 λιστών, μηνυμάτων και παραθύρου εργασιών**. Του ανήκουν το M20 (όρια χωρίς σελίδες), το κομμάτι «χειροποίητοι πίνακες» του L29 και η σελιδοποίηση της οθόνης υλικών από το M19. Πιθανή επικάλυψη και με το M22 (οθόνες σφάλματος) και το M9/L16 (εκκρεμείς εργασίες). Αυτό το σχέδιο δεν τα αγγίζει· όπου χρειάζεται διόρθωση στο ίδιο αρχείο (π.χ. H11 στο `finance/page.tsx`) αλλάζει μόνο το ερώτημα, όχι τον πίνακα.
