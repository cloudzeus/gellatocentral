# Gelato System — Ενιαίο λειτουργικό σχέδιο εμπορικού SaaS MVP

Ημερομηνία: 2026-11-24
Κατάσταση: λειτουργική απόφαση και πλαίσιο παράδοσης — όχι τεχνική υλοποίηση
Πεδίο: Συναλλασσόμενοι, Αγορές, Πωλήσεις, Viva και Οικονομικά σε multi-tenant SaaS

## 1. Σκοπός και δεσμευτικές αποφάσεις

Το σχέδιο ορίζει πώς το Gelato System καλύπτει εγγενώς τον εμπορικό κύκλο μιας επιχείρησης γελάτου, χρησιμοποιώντας τα ήδη σχεδιασμένα υποσυστήματα παραγωγής, αποθέματος, συνταγών, ιχνηλασιμότητας, POS και οικονομικών.

### Κλειδωμένες αποφάσεις

1. **Το SoftOne είναι μόνο λειτουργικός μπούσουλας.** Δεν προβλέπεται διασύνδεση, συγχρονισμός, απομακρυσμένη αποθήκευση ή αντιγραφή του μοντέλου δεδομένων του.
2. **Το Gelato System είναι η κύρια πηγή εμπορικών δεδομένων.** Πελάτες, προμηθευτές, παραγγελίες, παραδόσεις, παραστατικά, υπόλοιπα, απόθεμα και κόστος δεν αντιγράφονται σε παράλληλο ERP.
3. **Η Viva είναι υποδομή πληρωμών και φορολογικής διαβίβασης**, όχι πηγή εμπορικού ή λογιστικού υπολοίπου.
4. **Η απομόνωση tenant είναι υποχρέωση κάθε ροής**, συμπεριλαμβανομένων αναζητήσεων, αρχείων, callbacks, exports, reports και εργασιών πλατφόρμας.
5. Το πρώτο MVP μετριέται από **κλειστές και συνεπείς επιχειρησιακές ροές**, όχι από πλήθος οθονών ή ομοιότητα με γενικό ERP.

## 2. Κοινή ορολογία και όρια ευθύνης

| Όρος | Λειτουργική σημασία |
|---|---|
| Tenant / Organization | Μία συνδρομήτρια επιχείρηση. Αποτελεί το απόλυτο όριο εμπορικών δεδομένων |
| Party | Ενιαία καρτέλα συναλλασσομένου με έναν ή περισσότερους ρόλους: πελάτης, προμηθευτής, franchisee, συνεργάτης |
| TradeItem | Συγκεκριμένο εμπορικό/συσκευασμένο είδος. Μπορεί να ανήκει στον κοινό κατάλογο ή να είναι ιδιωτικό του tenant |
| GenericItem | Το είδος που χρειάζεται η συνταγή και μετρά η αποθήκη του tenant |
| Product | Είδος πώλησης POS. Δεν ταυτίζεται αυτομάτως με GenericItem ή TradeItem |
| Παραγγελία | Εμπορική δέσμευση. Δεν συνεπάγεται από μόνη της απόθεμα, παραστατικό ή οφειλή |
| Δέσμευση αποθέματος | Μείωση του διαθέσιμου για επιβεβαιωμένη ζήτηση, χωρίς αποθεματική έξοδο |
| Παράδοση / παραλαβή | Πραγματική φυσική ροή, με ποσότητες και παρτίδες |
| Παραστατικό | Εμπορικό και φορολογικό έγγραφο με αμετάβλητα snapshots |
| Απαίτηση / οφειλή | Οικονομικό υπόλοιπο από εκδοθέντα παραστατικά και πιστωτικά |
| Πληρωμή | Πραγματική είσπραξη ή καταβολή χρημάτων. Δεν ταυτίζεται με το τιμολόγιο |
| Allocation | Αντιστοίχιση μέρους ή όλης της πληρωμής σε συγκεκριμένο παραστατικό |
| Settlement | Διακανονισμός π.χ. καρτών προς τράπεζα. Δεν αποτελεί νέα πώληση |
| Snapshot | Ιστορική αποτύπωση τιμής, ΦΠΑ, στοιχείων και όρων τη στιγμή του εγγράφου |

### Διαχωρισμός καταστάσεων

Κάθε συναλλαγή μπορεί να έχει ανεξάρτητες καταστάσεις:

- εμπορική,
- αποθεματική,
- φορολογική,
- πληρωμής,
- τραπεζικού διακανονισμού.

Καμία δεν συνάγεται σιωπηρά από μία άλλη.

## 4. Μη διαπραγματεύσιμο SaaS/multi-tenant συμβόλαιο

| Περιοχή | Υποχρεωτικός κανόνας |
|---|---|
| Tenant isolation | Κάθε εμπορική εγγραφή ανήκει ρητά σε έναν οργανισμό. Κάθε read/write/report/export περιορίζεται σε αυτόν |
| Συσχετισμοί | Party, παραγγελία, παραστατικό, πληρωμή, αποθήκη και είδος πρέπει να ανήκουν στον ίδιο tenant |
| Store/warehouse scope | Ο χρήστης ενεργεί μόνο εντός των καταστημάτων και αποθηκών που του έχουν δοθεί |
| RBAC | Ο ρόλος καθορίζει την επιτρεπόμενη ενέργεια. Το κρυφό μενού δεν είναι security boundary |
| Module access | Το πακέτο συνδρομής ανοίγει ή κλείνει πραγματικά τη λειτουργία, όχι μόνο την οθόνη |
| Κοινός κατάλογος | Κοινά είναι μόνο δεδομένα αναφοράς. Τιμές, συμφωνίες, mappings, απόθεμα και ιστορικό είναι tenant-specific |
| Audit | Έγκριση, εξαίρεση, ακύρωση, αναίρεση και support access έχουν χρήστη, χρόνο και αιτιολογία |
| Idempotency | Retry, διπλό submit και επαναληπτικό callback δεν δημιουργούν δεύτερη επιχειρησιακή συνέπεια |
| Αρχεία | OCR, PDF, attachments και exports ανήκουν σε συγκεκριμένο tenant και δεν κοινοποιούνται δια-tenant |
| Δημόσιες προσβάσεις | B2B, RFQ, βιτρίνα και δημόσια έγγραφα έχουν συγκεκριμένο σκοπό, tenant, λήξη και δυνατότητα ανάκλησης |
| Viva | Merchant, source, terminal, πληρωμή και callback συνδέονται με τον σωστό οργανισμό πριν από οποιαδήποτε εγγραφή |
| Πλατφόρμα | Συνδρομές και pay-per-use χρεώσεις δεν αναμειγνύονται με τα έσοδα του tenant |
| Support | Πρόσβαση προσωπικού πλατφόρμας σε tenant είναι εξαιρετική, χρονικά περιορισμένη και καταγεγραμμένη |
| GDPR | Η διαγραφή προσωπικών δεδομένων δεν καταστρέφει νόμιμα διατηρούμενο φορολογικό ιστορικό |

- Παρτίδες, λήξεις, FEFO, HACCP παραλαβής και σταθμισμένο κόστος.

## 9. Roadmap και εξαρτήσεις

### Milestone 0 — SaaS θεμέλια

Tenant isolation, RBAC, store/warehouse scope, module gating, audit, idempotency, κοινός stock writer και διαχωρισμός πλατφόρμας/tenant.

**Έξοδος:** δύο tenants δεν αλληλεπιδρούν με ξένα IDs· κλειστό module μπλοκάρει τη λειτουργία· retry δεν διπλασιάζει εγγραφές.

### Milestone 1 — Συναλλασσόμενοι

`PTY-01–05`, `PTY-08`.

**Εξάρτηση:** Milestone 0.
**Έξοδος:** αξιόπιστοι πελάτες/προμηθευτές και εμπορικοί όροι ανά tenant.

### Milestone 2 — Αγορές

`PRC-01–07`.

**Εξαρτήσεις:** Milestone 1, αποθήκες, παρτίδες, κοινός κατάλογος/mappings.
**Έξοδος:** πλήρης αγορά, παραλαβή, τριπλή συμφωνία, απόθεμα, κόστος και οφειλή.

### Milestone 3 — Πωλήσεις

`WHL-01–08`.

**Εξαρτήσεις:** Milestones 1–2, σειρές και φορολογικό πλαίσιο.
**Έξοδος:** πλήρης χονδρική με δεσμεύσεις, παραδόσεις, παραστατικά και απαιτήσεις.

### Milestone 4 — Viva/Οικονομικά

`VFI-01–06`, `VFI-10`.

**Εξαρτήσεις:** απαιτήσεις/οφειλές από Milestones 2–3 και επαληθευμένα Viva δείγματα.
**Έξοδος:** νόμιμη τιμολόγηση, εισπράξεις/πληρωμές και οικονομικό κλείσιμο.

### Milestone 5 — Hardening και go-live

Διπλό tenant σενάριο, αρνητικοί έλεγχοι, retries/callbacks, GDPR, support, exports, backup/restore και τελική συμφωνία αριθμών.

## 11. Κεντρικό σενάριο αποδοχής με δύο tenants

Όλα τα δεδομένα είναι τεχνητά και όλες οι Viva/myDATA ενέργειες γίνονται σε δοκιμαστικό περιβάλλον.

### Κοινά δεδομένα

- Κοινό εμπορικό είδος `CAT-DEMO-01`, χωρίς κοινή τιμή ή απόθεμα.
- ΦΠΑ 24%.
- Tenant A: τιμή αγοράς 1,00 €, τιμή χονδρικής 3,00 €, πελάτης με όριο 100 €.
- Tenant B: τιμή αγοράς 2,00 €, τιμή πώλησης 4,00 €.
- Ίδιο δοκιμαστικό ΑΦΜ προμηθευτή στους δύο tenants, αλλά διακριτές καρτέλες.
- Διαφορετικοί merchants/sources/terminals και περιορισμένοι χρήστες ανά tenant.

### Tenant A — αγορά

## 12. Υποχρεωτικοί αρνητικοί και operational έλεγχοι

- Άμεσο ID άλλου tenant δεν επιστρέφει δεδομένα.
- Store/warehouse restricted χρήστης δεν ξεπερνά το scope του ούτε με άμεση ενέργεια.
- Ξένος πελάτης, προμηθευτής, τιμοκατάλογος, αποθήκη ή παρτίδα δεν συνδέεται με έγγραφο.
- Διπλό submit, retry, ίδιο MARK ή ίδιο Viva callback δεν δημιουργεί δεύτερη συνέπεια.
- Μη παραδοθείσα ποσότητα δεν τιμολογείται.
- Μη επιτυχής πληρωμή δεν μειώνει υπόλοιπο.
- Μη εξουσιοδοτημένη υπέρβαση πίστωσης, παράδοσης, επιστροφής ή reopen απορρίπτεται.
- Κλειστό module δεν διαγράφει ιστορικό, αλλά απενεργοποιεί πραγματικά τη λειτουργία.
- Support πρόσβαση είναι χρονικά περιορισμένη και καταγεγραμμένη.
- GDPR αίτημα δεν διαγράφει νόμιμα διατηρούμενο φορολογικό ιστορικό.
- Export περιλαμβάνει μόνο τον σωστό tenant και περίοδο.
- Backup/restore επαναφέρει δεδομένα χωρίς ανάμειξη tenants ή αλλαγή υπολοίπων.
- Χρεώσεις πλατφόρμας δεν εμφανίζονται ως πωλήσεις tenant.

## 13. Τελικό Definition of Done και Go/No-Go

Το MVP θεωρείται ολοκληρωμένο μόνο όταν:

1. Όλες οι P0 ροές ολοκληρώνονται end-to-end.
2. Το σενάριο δύο tenants αναπαράγει ακριβώς τα αναμενόμενα νούμερα.
3. Δεν υπάρχει διαρροή σε query, search, detail, file, report, export, callback ή εργασία πλατφόρμας.
4. Δεν υπάρχουν διπλά παραστατικά, πληρωμές, κινήσεις, COGS ή settlements.
5. Απόθεμα, κόστος, πωλήσεις, απαιτήσεις, οφειλές και ταμείο συμφωνούν χωρίς χειροκίνητη διόρθωση.
6. Κάθε έγκριση, εξαίρεση, ακύρωση, αναίρεση και reopen έχει audit.
7. Οι Viva/myDATA τύποι που ενεργοποιούνται έχουν επαληθευτεί ξεχωριστά.
8. Backup/restore, support access, module gating και GDPR έχουν δοκιμαστεί πραγματικά.

**Αυτόματο No-Go:** οποιαδήποτε διαρροή μεταξύ tenants, διπλή χρηματοοικονομική εγγραφή, μη εξηγήσιμη απόκλιση υπολοίπου ή ανοιχτό P0 σφάλμα σε παραστατικά, απόθεμα, πληρωμές ή RBAC.

## 14. Μελλοντικές αποφάσεις που δεν μπλοκάρουν το P0

- Αν και πώς μεταφορικά/λοιπά έξοδα αγοράς επιμερίζονται στο κόστος αποθέματος.
- Ποιοι ρόλοι εγκρίνουν πιστωτικές και οικονομικές υπερβάσεις πέρα από το βασικό P0 policy.
- Πότε ενεργοποιείται η ηλεκτρονική B2B είσπραξη μέσω Viva.
- Ποια προχωρημένα δρομολόγια, CRM, MRP και reports μπαίνουν στο Release 5 μετά τη σταθεροποίηση.

Το P0 δεν εξαρτάται από τις παραπάνω αποφάσεις, αρκεί να μην παρουσιαστούν οι σχετικές λειτουργίες ως ήδη διαθέσιμες.
